# Security Policy

## Supported versions

This project is in **public alpha**. Only the **current alpha** on the default branch
(`main`) is supported. Older commits and branches are not maintained for security fixes.

## Reporting a vulnerability

**Please do not report security vulnerabilities, credentials, or secrets in public
GitHub issues or pull requests.**

- Use **GitHub Private Vulnerability Reporting** for this repository
  (repository → **Security** tab → **Report a vulnerability**), if enabled.
- If private reporting is not available, contact the repository maintainer **privately
  through GitHub** (via their GitHub profile) to arrange a secure channel before sharing
  any details.

When reporting, please include enough detail to reproduce the issue. **Do not include
secret values** (API keys, tokens, credentials) in the report — describe the exposure
instead.

## Scope

- This policy is for **security vulnerabilities** (e.g. credential exposure, unsafe data
  handling, injection).
- **Religious-content errors are not security issues.** To report a mistake in sourced
  content, use the **content correction** issue template instead.

## What we do not promise

- There is **no guaranteed response time** and **no bug bounty**. This is a volunteer
  alpha project; we will make a good-faith effort to review valid reports.
